# 一段网页文字，进卡片之前经历了什么

*剪藏管线的工程手记*

> 设计的来历在《[用代码写一本旧书](design-notes.zh.md)》。English version: [engineering-notes.md](engineering-notes.md).

真实的网页很少是干净的文档：看着像列表的东西只是一堆并排的标签，选区抓回来是空的，扩展自己也随时会被浏览器杀掉。剪藏的工程，先还原作者原本的结构，再让文字在卡上站稳。这份手记写给做剪藏、做浏览器扩展的人：沿一段文字从选区到成图分八幕，每条一个真实踩过的坑和一个可迁移的手法，都能在源码里对到行。

---

## 一、把选区找回来

选区是整条管线的源头，而浏览器给的选区并不可靠：跨 shadow DOM 边界的选区被悄悄重定向到宿主边界，`cloneContents()` 克隆出一片空白；页面自己的脚本会抢先清掉它；画布应用根本没有 DOM 选区。

- **三条采集通道各有兜底**：鼠标抬起时先同步克隆一份选区存下，50 毫秒后再读，页面自己的脚本可能已经把选区清掉；键盘选区走 keyup；Google Docs 这类画布应用没有 DOM 选区，从 copy 事件的剪贴板 HTML 里取。
- **copy 路径走同一条管线**：有真实 DOM 选区时，站方的复制按钮和 ⌘C 也走同一个提取函数，产物逐字相同，被去重吸收；走降级路径就会冒出第二张格式不同的卡。
- **右键菜单的选区文本压平了换行**：菜单拿到的只是纯文本；先向内容脚本要鼠标抬起时缓存的 Markdown，脚本不在才退回纯文本。
- **冷门的正确答案**：`Selection.getComposedRanges({ shadowRoots })` 能重建真正落在 open shadow root 内部的 Range，代码块的高亮与语言标签得以保全；候选元素要包含 `anchorOffset` 处的子节点，宿主级重定向恰恰把选区停在那里。MDN 把代码块装进 `<mdn-code-example>` 的那天，这条路救回了它。
- **语言识别也要会穿墙**：从代码节点向上爬时用 `getRootNode().host` 穿过 shadow 边界，才能在自定义元素外找到 `language-` 类名。

## 二、给脏结构整形

DOM 上的结构常和眼睛看到的不一样：列表不是列表，重复不像重复，第一个标题不是标题。修复一律做在克隆件上、按站点分域，别的网站不受影响。

- **按站点认列表**：有的内容平台用 `<ul> > <section>` 冒充 `<li>`，Turndown 认不出，整个列表散成段落：按 `location.hostname` 分站点，先把 section 归一化回 `<li>` 再转写。
- **收回孤儿列表项**：选区切穿列表时，`cloneContents()` 保留 `<li>` 却丢掉父级 `<ul>`：连续的孤儿 `<li>` 用一个游标缓冲收进新的列表。
- **去重之前先归一**：同一段落会从两条路径抓成「看似不同」的重复（围栏与纯文本、空白差异）：去重键剥掉围栏行、压缩空白之后再比对。
- **第一个 h1 未必是标题**：在 GitHub 上它是全站搜索框，剪出来的 `.md` 标题成了「Search code, repositories…」，文件名跟着退成一串 UUID。改法是先在正文区（`article`／`main`／`[role=main]`）里找 h1，且不落在搜索、导航、页眉页脚、表单与边栏之内，找不到再退 `og:title`，最后才用 `document.title`。
- **切进引文块或代码块要补外壳**：克隆只给内层，Turndown 失去语义；按共同祖先只补最内层缺失的一层，代码块还要补回 code 标签并带上语言类。

## 三、转写的规矩

HTML 到 Markdown 的转写有几条规矩，多数来自具体的网站。

- **站点各有各的怪癖**：Substack 的斜体写成 `_` 会留下孤儿下划线，于是强制 `emDelimiter:'*'` 并删掉 `<u>`；X 的图片会泄漏成 `![]()` 噪音，直接移除 `img` 与 `figure`；MDN 的链接 title 里带括号，会把下游正则带崩，于是规则永远只发 `[text](url)`，不发 title。
- **链接出门前绝对化，且只放行 http 与 https**：相对链接用 `new URL(href, location.href)` 绝对化，否则导出的 `.md` 在本地笔记库里全是死链；行内正则要认 Turndown 的三种输出，普通链接、URL 含括号时的尖括号形、自动链接；mailto、javascript 和相对路径一律留文字丢链接，顺手关掉一个注入面；页内锚点降级成纯文字，引用角标整个消失。
- **转义要管往返**：Turndown 交给规则的内容已经转义，引文角标到规则里是 `\[4\]`，正则要同时认两种形态，有序列表被写成 `1\.`，渲染前先还原；反过来，URL 里的裸括号出门前要转义，Turndown 加的 `\*` 在渲染前先还原，不然粗体显示成裸星号，RTL 文本里的 `\[ترميم\]` 裸反斜杠尤其显眼。
- **语言标记挂在 pre 上，Turndown 看不见**：围栏规则只读 code 的类名；转写前把 pre 级的语言提升到 code，整块选中和部分选中两条路径共用同一个正则。
- **清洗做在出口**：不换行空格、空段、空链接的清洗在渲染、导出、复制三处各做一次，存储里保留原文供编辑；剥空文字链接时用负回顾护住图片语法。
- **分叉要带到底**：代码块与引用块携带的是行数组，不是纯文本字段，把它们喂给按行处理的函数会抛错。第一张围栏卡片落进列表之后，整个纯文本复制都跟着失效，按钮看上去像是死了。

## 四、先保护，再渲染

侧栏的 Markdown 渲染没有用现成的库。`marked`、`markdown-it` 这类把 Markdown 一次转成 HTML，而这里要在转换的中途插进四件事：占位符保护、盘古之白、首字下沉的判定、技术标识符的防断行——每一件都要求能指定转义发生在哪一步，而库把这一步封住了。于是这条链路自己写：块级解析 55 行，行内 85 行，组装 42 行。

行内 Markdown 的各条正则会互相误伤：斜体规则吃掉 URL 里的下划线，代码里的 `*` 被当成粗体标记。

- **提取、占位、还原**：代码、链接、技术标识符先抽出来，各留一个 NUL 哨兵占位（`\x00C`、`\x00L`、`\x00N`），跑完所有危险正则再逐类归还。
- **嵌套要二次还原**：链接文字里自带的代码占位符，在还原链接时再还原一层，否则乱码漏到卡面。
- **顺序本身就是保护**：中西文之间补空格的盘古之白，被安排在链接与代码提取之后执行，URL 里永远不会被塞进空格。
- **纯文本复制里 URL 也要占位**：「文字 (网址)」的形态下，斜体规则会吃掉网址里的下划线，Learn_web_development 变成死链；网址先占位，剥完再原样还原。

## 五、侧栏卡片的版面

摘录落进侧栏的卡片之后，版面还会出错：高度会骗人，折叠线会切在半行，后加载的主题样式会顶掉语言规则。

- **常量跟着行高走**：长卡折叠的阈值写死在 220 像素，按拉丁与中文的行高量的，约七行半。Nastaliq 行距 2.5，六行就越线，短卡上冒出一个点开没有内容的「Read more」。字体还没加载完就测高也会偏大，面板宽度一变折叠线也不重算；现在字体就绪后重测一次，宽度变化也重测一次。
- **显式底线顶掉隐式**：给卡片补一个 `min-height`，是为了让单句短卡容得下右侧的动作列。整列卡片却被压成一条，正文漫出卡外。显式的 `min-height` 替换了 flex 子项默认的 `min-height:auto`，此后 `flex-shrink` 可以随意压缩它。补一行 `flex-shrink:0` 即可。
- **折叠线落在块边界上**：220 像素内取最后一个整块的底边为切点，低于 160 退到 200；切点离阈值超过 16 像素就贴回去，免得半行截断和「点开只多一行」。
- **主题样式后加载会顶掉语言规则**：基础样式之后再加载主题文件，同特异度时后来者胜；语言与方向规则用双写属性提高一档，主题文件一字不改。

## 六、在 MV3 里活下来

MV3 里没有常驻的后台：service worker 约五分钟空闲就被杀，重载后旧页面里的脚本成了孤儿，侧栏又是窗口级的东西。这一幕的条目，都是在这种生命周期里保住状态、堵住时间差。

- **侧栏启动前的碎片要排队**：冷启约 200 毫秒，后台先把碎片缓存，侧栏就绪后再灌；发送失败放回队首，等下一次连接。
- **异步存储首绘前拿不到**：一次性引导标志镜像一份到同步的 localStorage，脚本顶部同步挂上类名，否则元素先现身再被藏，闪一帧。
- **开侧栏必须贴着用户手势**：三个入口都先开侧栏再探活，探活不能等在前面，否则手势上下文丢失，浏览器拒开。
- **断连与关闭分开处理**：分不清这两件事，每次空闲都会误杀剪藏状态。拆解：`onDisconnect` 里只清端口引用，绝不下发状态；真关闭由侧栏卸载时的 `pagehide` 显式上报，并自带 tabId，因为竞态中的 onDisconnect 可能已把后台记录清空。
- **标志位会陈旧，用时再问一次**：内容脚本记的「侧栏是否打开」在导航和后台重启后失真，鼠标抬起时标志为假就再问一次；后台在页面加载完成和侧栏就绪前各主动推一次状态，堵住时间差。
- **侧栏状态挂在窗口上**：Chrome 的 side panel 本就是窗口作用域，windowId 是唯一真相，tabId 只负责跟随当前激活的标签；关闭时按窗口广播，不然其他标签会继续往队列里灌内容。
- **重载后向旧页重新注入**：扩展重载后，旧标签页里的 content script 成了孤儿，剪藏静默退化成纯文本：`onInstalled` 时向所有页面发一个 `PING`，只有本实例注入的脚本会应答，对不应答的页面按 manifest 的原始顺序重注入。主世界脚本跨扩展实例共享，重载后旧脚本还在跑，重注入会叠上第二个观察者，幂等守卫必须写在脚本内部；隔离世界随实例重建，不需要。
- **拦截与放行成对上**：内容级去重拦住换装的重复，但删卡与清空时要向所有页面广播重置，否则「误删想重剪」被静默卡死。

## 七、排上导出卡

钤印工作室里的导出卡是另一套排版。字进卡之后各丢过一次东西，首字、方向、字形；字体文件、编辑态和十二款的高度也各有一坑。

- **先问语种，再包首字**：首字下沉的包裹逻辑对所有语种一视同仁，而阿拉伯、天城文、谚文几档的样式表把下沉的那个字设成不显示。两条各自有理，合起来是删掉首字符：في 剩下 ي，홀로 剩下 로，एकांत 剩下 कांत。现在包裹之前先看语种，连笔文字与音节文字一律不包。
- **方向交给双向算法**：右起卡上的落款日期排成了「月-年-日」。内容与顺序都没错，容器没有声明 `direction:rtl`。声明之后，浏览器自会把数字与月名摆到位。
- **字体加载失败是静默的**：`@font-face` 的路径少写了 `-subset` 后缀，Nastaliq 无声退回系统 Naskh，四张成图带着错字形出去，自动检查跑了四轮都没报警。有辨识度的字形只能靠肉眼放大验。
- **每个字面按声明的样式核对**：Google Fonts 的样式表先列斜体，两枚文件存反，所有标签全成了斜体。
- **编辑态要豁免全局快捷键**：守卫只挡输入框，漏了可编辑区，编辑正文时空格切纸样、回车触发导出；补上可编辑判断。
- **十二款卡共用一个中位锚**：把每款卡隐藏着量出自然高度，取中位数为基准，高卡缩、矮卡最多放大 1.12 倍，同一段内容在十二款间切换不跳。

## 八、导出成图

最后一步，把卡变成一张图和一个文件名。

- **内容异步到达，拟合要多次重测**：存储晚于首次拟合，字体又晚于内容；字体就绪、字体加载完成、尺寸变化各触发一次重拟合，导出前再等一次字体就绪，并加忙碌态防连点。
- **缩放只在克隆件上重置**：html-to-image 量自然尺寸需要重置缩放，但重置只作用在库的内部克隆上：`transform` 清零、阴影剥离都发生在克隆件里，宽高钉死填满画布；预览里的卡不闪不跳。
- **画布尺寸有上限，像素比不能写死**：canvas 最大 16384 像素，三倍像素比下超长卡静默失败；曾做过按尺寸收缩像素比的防护，在一次整体回滚里一并撤掉；现行固定三倍，这个坑还开着。
- **截断长度要拿真标题量**：一句真实导出的标题正好 63 个字，先前的 40 太保守、常把整句斩断，而 64 仍在访达与路径长度的安全线内。收刀落在词边界上，`do-not-w` 收成 `do-not`。
- **导出页登记 opener 回到阅读页**：新标签页带上文章页作为 opener，关闭导出页时回到原文；opener 已关就不带 opener 重试。
- **本地预览靠内置示例，但测不出 CSP**：拿不到 `chrome.storage` 时落到内置示例数据上，`file://` 双击打开就是完整的开发预览。只是扩展页禁内联脚本，本地一切正常、装进扩展一片空白；脚本外提成文件，本地用等价的 CSP 头复现。
